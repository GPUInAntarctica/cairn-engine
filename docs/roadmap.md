# 路线图与进度 / Roadmap & Progress

目标：把 Cairn 从"能用但早"的基础推进到工业级引擎（对标 Unity）的能力。这份文件是
**唯一的进度账本**：路线图、每个增量的范围、以及"下一步做什么"都以它为准，CHANGELOG
负责记录每次改动的细节。

## 工作原则

1. **每个增量都具体可行。** 一次提交解决一个能说清楚的问题，范围小到可以完整验证。
2. **版本号不跳跃。** 即使在做内部路线图里靠后的层，公开版本号仍然按 `0.1.x` 递增；
   层号只用来组织主题，不当作版本号。每次增量是一个本地提交 + 一个注解 tag，先不推送。
3. **正确性由软件路径定义。** 软件光栅化器是参考实现，测试套件固定跑它。GPU 路径的
   存在意义是加速，不是引入第二套语义——两条路径之间任何画面差异都算 GPU 侧的 bug。
4. **改渲染必须两条路径都验。** 见文末"验证方法"。

## 阶段：性能与物理（0.3）

**已做**

- 绘制预算：不透明网格与阴影 caster 都实例化；贴图走 bindless 数组，因此合批的键只剩
  「网格 + 剔除模式」。一帧的绘制数由"物体数"变成"相邻同网格 run 数"。
- CPU 并行：进程级工作池，只用在"下标无关"的地方（软件光栅化的扫描行分带、后处理、
  天空/清除），输出与串行逐位相同。
- 观测：`Profiler` 覆盖 update/scripts/physics/render/gather/shadows/raster/post/gpu，
  `engine.profile` 读出快照并附带绘制计数与任务系统遥测。
- 物理正确性：连续碰撞检测（0.1.13）。逐刚体可选（`collisionDetection =
  Continuous`），用保守推进（conservative advancement）求真实碰撞时刻，而不是固定
  采样，所以薄墙挡得住、斜向命中也不会被包围盒提前截停。默认（Discrete）路径一行
  都不改。

**下一步候选**（按"缺口大小 × 可行性"排序）

1. **物理约束补齐。** 目前只有 `DistanceJoint`。Unity 侧对应的是 Hinge / Fixed /
   Configurable 关节，以及铰接体（articulated bodies）。
2. **碰撞体形状补齐。** 缺 MeshCollider / TerrainCollider。
3. **预制体逐属性覆盖。** 现在是模板 + 链接，改一个实例会牵动所有实例。
4. **贴图流送。** 纹理缓存目前是 512 条上限的 LRU（超过 512 帧未用即淘汰），
   还没有异步上传或按需降级。
5. **旋转与动态目标的 CCD。** 见"已知限制"。

> 已经具备（别重复做）：碰撞/触发回调（`OnCollisionEnter/Stay/Exit`、
> `OnTriggerEnter/Exit`，见 `engine/src/physics.cpp` 的 `NotifyCollision` /
> `NotifyTrigger`）、层与层矩阵、射线/重叠查询、角色控制器、刚体休眠。

## 阶段：工具链与素材创作（0.5）

**目标。** 让 Agent 只用 `cairn` 就能把游戏素材（精灵、瓦片、图标、UI 贴图、法线图）
画到可用，并且**不依赖视觉模型就能自检**：画一笔 → 看一眼 → 改一笔。

**为什么是它。** 引擎已经有底座：`editor/main/imaging.js` 是一套零依赖的分层栅格核心
（图层、合成、笔刷/形状/填充、Sobel 法线图、PNG/BMP 编解码），CLI 用 `image.*` 把它
暴露出来。但它是**给会用鼠标的人**设计的：反馈面近乎为零（`image.info` 只给直方图，
`image.pixel` 一次一个像素，Agent 看不见 PNG 只能盲画），绘制面又缺画素材最常用的
原语（多边形、渐变、镜像、翻转/旋转/裁剪、拼合、噪声），连"填充 + 描边"都要分两次
调用，而且描边居中会向内吃掉填充。

**已做（0.1.14）**

- **反馈面。** `image.preview` 把文档（或某一层）渲染成文本：`--scale` 个像素平均成一
  格（按 alpha 加权，透明不会冲淡颜色），可以输出 ascii 亮度阶梯、`--format blocks`
  的 Unicode 密度阶梯，或 `--format hex` 每格一个 `#rrggbb`。`image.info` 在直方图之外
  新增非透明包围盒、覆盖率、是否触碰画布边缘（被裁切）、左右/上下镜像对称（含不匹配
  计数）、8 个主色（每通道 4 bit 量化），`--spans` 给出每行/每列的内容起止列；
  `--layer` 只看一层。
- **形状。** `image.draw.path`：顶点来自 `--points`（`"x,y x,y …"`、`"x,y;x,y"` 或
  JSON），或由 `--sides --cx --cy --radius --rotation --inner` 直接生成正多边形/星形；
  填充用非零环绕规则，自交的星形照样实心。`--filled` 与 `--stroke N` 可一次成型，描边
  画在形状**外侧**（`--strokeColor` 可另给描边色），所以填充不会被描边吞掉；
  `--closed false` 画折线。旧行为不变：不给 `--stroke` 时 `--filled` 仍只填充，
  `--brush` 描边仍居中。

**剩余步骤**

| 步 | 内容 | 关键命令 | 验收 |
| --- | --- | --- | --- |
| 3 | **组合与变换**：镜像绘制、翻转/旋转/裁剪、把另一张图或另一层盖到当前文档 | `image.draw.* --mirror`、`image.flip/rotate/crop`、`image.stamp` | 对称角色只画半边；精灵图由多张小图拼出 |
| 4 | **纹理素材**：种子噪声、线性/径向渐变、调色板量化与抖动 | `image.draw.noise --seed`、`image.draw.gradient`、`image.palette` | 同 `--seed` 逐位可复现；无缝瓦片可验证 |
| 5 | **闭环文档**：一份 Agent 绘画教程 + "画 → 自检 → 修正"的完整示例 | `docs/` 新章节 + README 指引 | 照抄示例能产出一个可用的精灵与一张瓦片 |

**约束与验收（沿用仓库既有规则）**

- 每个新命令都要声明 summary、参数 schema、示例，并跑 `npm run docs:cli` 重生成
  `docs/cli.md` 参考表（规则 3）。
- CLI 行为进 `test/cli.js`（规则 1）。`imaging.js` 是编辑器图像编辑器与 CLI 的共用核心：
  新原语要么两条路径都能用，要么在文档里写明只面向 CLI——0.1.14 的预览/形状原语属于
  后者（编辑器图像编辑器有自己的 canvas 渲染器），已在 `docs/cli.md` 写明。
- **确定性**：同样输入 → 同样像素；噪声走 `--seed`，不依赖时间或隐式随机源。
- **纯增量**：不改变现有命令的语义，`image.*` 仍能在 `exec.run` 的同一会话里顺序组合。
- **反例验收**（这才是"更好地使用"的判据）：给一个只用 CLI 的任务，例如"画一个
  32×32、带上下高光的金币"，Agent 靠 `image.preview` 自检就能收敛，全程不需要视觉模型。

## 验证方法

每个增量都按同一套流程验收，规则见 [AGENTS.md](../AGENTS.md)：

- **C++ 行为**：`engine/tests/engine_test.cpp` 里加一个用例（`npm run build` 之后跑
  `npm run test:engine`——`run-engine-tests.js` 不会自动重新构建）。
- **跨 addon/Node 的行为**：`test/smoke.js`。
- **CLI 行为**：`test/cli.js`；新增命令要声明 summary、参数 schema 和示例，并跑
  `npm run docs:cli` 重新生成 `docs/cli.md` 的参考表。
- **渲染改动**：两条路径都验。A/B 对比合并开关（`CAIRN_NO_INSTANCING=1`）必须逐位相同；
  与软件参考对比（边缘抗锯齿差异是既有现象）；GPU 路径在
  `VK_INSTANCE_LAYERS=VK_LAYER_KHRONOS_validation` 下必须干净——但记住**校验层干净不等于
  画面正确**，所以还要看像素。
- **接口改动**（`engine/include/cairn/*.h`）：算契约，必须加 CHANGELOG 条目 + 测试，且
  现有示例工程要保持能编译。

## 已知限制

- **0.1.5 的 Windows/MSVC 路径无法在本机（Linux）验证**，只能靠代码审查和 CI 覆盖。
- **bindless 表是软上限。** 场景路径的贴图数组各 512 槽；一帧里引用的
  `(贴图, 采样器)` 对超过这个数量时会抢占最近最少使用的槽位（画面退化为槽位抖动），
  单帧真的超过 512 对时多出的绘制会取到白色贴图。这是刻意选择的降级方式：不崩溃、
  不静默丢贴图。
- **描述符索引是硬性设备要求**（`descriptorIndexing` 等）。不满足的设备会回退到软件
  路径并在日志里给出原因。
- **CCD 只扫平移，不扫旋转。** 高速旋转的细长物体仍可能把角速度扫进障碍。目标也只
  限于实体静态/运动学碰撞体（对应 Unity 的 `CollisionDetectionMode.Continuous`，
  不是 `ContinuousDynamic`），两个都开了 CCD 的动态物体之间仍是离散处理。保守推进
  迭代上限 32 次，掠过式逼近会安全地提前停住。
- **CCD 不接住「先接触、再被赋高速」的物体。** 步首已经贴着的障碍会被当作既有接触
  交给离散窄相（否则躺在地板上的物体会读到零碰撞时刻，连滑动都会被冻住）。因此一个
  已经贴着墙的刚体，如果脚本在同一步把它的 `velocity` 写成指向墙内的大值（或
  `AddImpulse`），那一步会穿过去——正常流程里接触冲量早就把法向速度清零了，只有脚本
  直接改写才会造成这个状态。
- **图形工具的 `--stroke` 与 `--brush` 语义不同。** `--stroke N` 的描边整体画在形状
  外侧（这是让"填充 + 描边"不互相吃的前提），而 `--brush N` 是旧行为、描边居中，两者
  都保留；新脚本用 `--stroke`。
- **外侧多边形描边是 miter 偏移（上限 4×）。** 尖角会被切平；高度自交的多边形偏移后
  可能自相交，此时按"偏移多边形 − 原多边形"的同心环绘制，仍是形状外一圈，但不保证
  严格等宽。`image.preview --scale` 是块平均而不是重采样，所以一格里的颜色是那块像素
  的平均值，不代表其中任何一个像素。
